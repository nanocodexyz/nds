# Decisions

- nds is the nanocode design system (nanocodexyz/nds, public, 2026-11-09), asked for by Georgios: "similar to how tempoxyz/tds works, extract a nanocodexyz/nds public repo that has our design system components which we use in the nanocode-site (combined with nanocode-ts which has headless styleless versions of these), move all the zyzz themes into nds, so that the story is easy demos, composing the headless with my own nds". It follows tempoxyz/ds (`@tempoxyz/ds`): one package of Zyzz styles, with the variables in `vars.ts`, the bound helpers in `zyzz.config.ts`, components in `components/`, fonts shipped with the package, and a playground. It leaves out what tds needs and nds does not: a mobile surface, Figma sync, an Oxlint plugin, icons and browser test suites.
- The sources came from two repositories. From nanocodexyz/nanocode-ts at 07238e5 (`src/react/`): `Theme.ts` (now `vars.ts` and `zyzz.config.ts`), `Skin.ts`, `Skin.styles.ts`, `Machines.styles.ts`, `Themes.ts` with `ChatGpt.styles.ts`, `Claude.styles.ts` and `Gemini.styles.ts`, `Site.tsx` with `Site.styles.ts`, `Agent.tsx`, `Clones.tsx` and `clones/`. From nanocodexyz/nanocode-site at 2b3728f: `src/components/Kbd.tsx` and `mdx/Callout.tsx`, `Cards.tsx`, `Tabs.tsx` and `Code.tsx` (now `CodeBlock.tsx` and `Diagram.tsx`), the article rules of `src/pages/Docs.tsx` (now `Prose`), `src/Theme.ts` (now `Highlight.ts`) and `public/fonts/CommitMono-VF.woff2` with its `OFL.txt`. The history starts here, because nanocode-site is private and its history is not this repository's to publish.
- The line between the two packages: nanocode-ts keeps behavior (the headless components of `nanocode-ts/react` and `nanocode-ts/machines/react`, their hooks, the `Skin` contract of part names) and nds takes every Zyzz definition. `Agent` and the clones moved too, because they import the skin and carry their own stylesheets: a whole styled chat is a look, not behavior. Their imports of nanocode-ts's modules became imports of its public entrypoints (`nanocode-ts` for the `Contracts` types, `nanocode-ts/client`, `nanocode-ts/machines`, `nanocode-ts/machines/react`, `nanocode-ts/react`, and `nanocode-ts/highlight` for the highlighter `Agent` loads), so nds needs nothing private from it. nanocode-ts is an optional peer dependency: only `nds/skin`, `nds/themes`, `nds/clones` and `nds/agent` import it. nds builds against nanocode-ts build-2539c55, the first release without the looks (its commit 2539c55 removed them there).
- Entrypoints: `nds` (`tokens`, `style`, `variants`, `vars`, the keyframes `ellipsis`, `flicker`, `pulse` and `spin`, and `Callout`, `Card`, `Cards`, `CodeBlock`, `Diagram`, `Kbd`, `Prose`, `Tab`, `Tabs`), `nds/site` (`Header`, `Main`, `Page`, `Title`, `Lead`, `Demos`, `styles`, `origin`, `sections`, `demos`), `nds/skin`, `nds/themes`, `nds/clones`, `nds/agent`, `nds/highlight`, `nds/zyzz.css` and `nds/fonts/CommitMono-VF.woff2`. They map to nanocode-ts's old ones as `nanocode-ts/react/theme` to `nds`, `/react/skin` to `nds/skin` (its re-exports of the theme helpers are the root's now), `/react/themes` to `nds/themes`, `/react/site` to `nds/site`, `/react/clones` to `nds/clones`, `/react/agent` to `nds/agent` and `/react/zyzz.css` to `nds/zyzz.css`.
- `nds/site` dropped `Docs`, `Block`, `Diagram`, `Cards` and `Card`, which the demos' How It Works pages used until those pages moved to nanocode.xyz (durable-cloudflare f18f3ba, durable-vercel 071cf6e) and no host imported since. The root's components, which nanocode.xyz renders its documents with, cover them: `Prose`, `CodeBlock`, `Diagram` (with its zoom dialog), `Cards` and `Card`.
- The document components take what the site's own modules supplied as props, so nds imports no router and no MDX pipeline. `Card` takes `link`, the component that renders its anchor (`'a'` by default, the site's router `Link` there). `CodeBlock` takes `code`, `html` (highlighted markup), `label` and `text` (what Copy writes) where the site's `Code` read `data-*` attributes off an MDX `pre` child, and `Diagram` takes `svg`. `Prose` takes `as` (`article`, `div` or `section`). `Callout` keeps `data-callout`, the attribute the site's Markdown pipeline writes on a blockquote.
- The Zyzz config keeps the ID `nanocode`, so the variables stay `--z-nanocode-*` and the scope `z-theme-nanocode-base`: `Themes.ts` names those variables, and hosts' own stylesheets may. Only the package ID changed, to `nds`.
- The build is nanocode-ts's, which every host's compiler already reads: `tsc -p tsconfig.build.json` writes `dist/`, then `zyzz build dist --package-id nds` (with `react` and `nanocode-ts` external) rewrites the modules and writes a stylesheet and a `.zyzz.json` contract beside each and `zyzz.css` with all of them, because Zyzz does not compile modules inside `node_modules`. `scripts/build.ts` copies that output and `src/fonts` over `dist/`. Zyzz is a dependency pinned to 0.0.40, the version the hosts compile with. tds builds with Zile and a script over `zyzz/node`'s `Host`, which adds per-domain staging nds has no use for with one domain.
- `zyzz.config.ts` imports `type Config` and `type Vars` from `zyzz` without using them: `tsc` needs the names in scope to write the declaration of `style`, `variants` and `vars`, and fails with TS2883 without them.
- Components keep `namespace styles {}`, as nanocode-site and tds write them, and the skins keep their `*.styles.ts` modules, whose exports are the skin's parts. So the sources are not erasable-syntax-only as nanocode-ts's are, and nothing runs them under Node's type stripping: hosts take `dist/`.
- Releases are nanocode-ts's kind: `npm run release` builds a clean checkout and publishes the GitHub release `build-<commit>` with `nds-<commit>.tgz`, and a host pins that URL. The package is not on npm.
- Hosts declare the Commit Mono face themselves, as they did, and nds ships the file (`nds/fonts/CommitMono-VF.woff2`). A `fontFace` in `zyzz.config.ts` would reach every host through `zyzz.css`, beside the face and the preload link each host already declares for the copy it serves, and a second declaration of the family would win over the preloaded one.
- The playground (`playground/`, `npm run dev`) is one Vite page compiled from `src/` through aliases, not from `dist/`: the header, the tokens, the document components, and nanocode-ts's headless `Chat` under each of the seven themes with a scripted transport (reasoning, one `Bash` call, a streamed answer with a code fence). Checked on 2026-11-09 in Chrome: the nanocode and Claude themes rendered the turn with their own cells, bullets and composer. `npm run check:types` and `npm run build` passed (135 files from `zyzz build`, `dist/zyzz.css` 156 KB).
- Four repositories moved to nds on 2026-11-09. nanocodexyz/nanocode-ts (2539c55, release build-2539c55) removed the modules that moved here, its seven `./react/*` exports for them, `scripts/zyzz.mjs` and its `zyzz` dependency. nanocodexyz/durable-cloudflare (cbeb213) and nanocodexyz/durable-vercel (51f5445) take the release tarball build-777c987 beside nanocode-ts build-2539c55 and changed three imports each: `Agent` from `nds/agent`, the page chrome from `nds/site` and the stylesheet from `nds/zyzz.css`. Both built, passed `npm run drill`, and rendered their nanocode, ChatGPT and Claude pages in Chrome under `wrangler dev` and `next start`; durable-cloudflare's `app.css` is 134,813 bytes, where nanocode-ts's stylesheet made it 117,355, because `zyzz.css` also carries the document components. nanocodexyz/nanocode-site (acd4c7d) takes the sources instead: it checks nds out at `nds-revision.json` beside its nanocode-ts checkout and aliases `nds` and `nds/skin` to `src/`, so its own `zyzz/vite` compiles only the rules its pages use, 75,638 bytes of CSS for the whole site against the 155,845 bytes of `zyzz.css`. It exports nds's `style`, `variants` and `vars` from its `zyzz.config.ts`, which Zyzz follows through the re-export, and deleted its own `Kbd`, `Callout`, `Cards`, `Tabs`, code block, diagram viewer, article rules and code colors. None of the three sites was deployed with the change.
- `zyzz.css` holds every module's rules, and `zyzz build` writes each module's stylesheet with the variable scope repeated (27 scopes of 1.7 KB in `zyzz.css`), as nanocode-ts's did. A host that takes the tarball therefore ships the three chat themes (72 KB) whether or not it renders them. tds avoids both: its build compiles the stylesheet once more with `css` only, where scopes are declared once, and appends an import of each module's own rules to the module, so a bundle carries only the components it uses. Here `zyzz build --css-only` over `dist/` stops at "CSS-only named stylesheet declarations require an explicit id" for the keyframes, so that is not done.
- The demo chat discloses its connections on request, asked for by Georgios on 2026-11-09: "the demo pages are bloated, use progressive disclosure for connecting things, bullet pointed communication, link out to prompts and docs, this is ultimately all just demos". Under the nanocode theme `Agent` no longer renders the idle rows of `PlanConnect`, `HandConnect` and `Unlock` below the transcript. One Connect action (and `/connect`) opens a picker with Tempo Wallet, ChatGPT plan, Claude plan and Your machine, each with its state. A panel appears only while it has something to show: `PlanConnect` for the provider whose sign-in is pending, `HandConnect` while its command is open or it has an error, and `Prompts` as before. A plan error is noted in the transcript once the visitor has asked for a plan, so a deployment without the plan routes says nothing on load. `nds/site` gains `Points` (a bulleted list with accent markers) and `Links` (a wrapping row of links), which the demo pages use where they had one long `Lead`. Checked on 2026-11-09 against durable-cloudflare's built page in headless Chromium: four bullets, the chat with no rows below it, and the Connect picker listing the four choices. `npm run check:types` and `npm run build` passed.
- The README shows the playground (`assets/page.png`) and the chat under the nanocode, ChatGPT and Claude themes (`assets/chat-*.png`), captured at 1000 px wide and 2x from `npm run dev` with headless Chromium on 2026-11-09. `assets/` is not in the package's `files`.
